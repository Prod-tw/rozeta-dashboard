Rozeta API - Meeting Transcription and Translation Service

This API provides comprehensive meeting transcription and translation services with subscription management and payment processing capabilities.

Features:

  • Real-time meeting transcription
  • Multi-language translation support (34 languages)
  • Subscription-based credit management
  • Stripe payment integration
  • OAuth authentication (Google)

Create meeting

Create a new meeting

Creates a new meeting with specified language configuration and optional context. Context information improves transcription accuracy for domain-specific terminology.

Context options:

  • Use 'context_preset_id' to load a saved context preset (recommended for recurring meetings)
  • Use 'context' to provide inline context data
  • If both are provided, 'context_preset_id' takes priority

Language requirements:

  • Source and target languages must be different
  • At least source and target must be specified

Two-way translation:

  • When enabled, translations occur in both directions (source to target and target to source)
  • Useful for bilingual meetings where both parties need translations

Complete meeting

Complete a meeting

Marks an active meeting as completed. This transitions the meeting status to 'completed' and records the end timestamp. Once completed, a meeting cannot be modified or receive new transcriptions/translations until it is resumed.

What happens when completing:

  • Meeting status is changed to 'completed'
  • End timestamp (ended_at) is recorded
  • MeetingCompleted event is dispatched
  • All existing transcriptions and translations are preserved
  • Meeting becomes read-only (cannot receive new data)

Requirements:

  • Meeting must NOT already be in 'completed' status
  • Only the meeting owner can complete the meeting
  • Typically used to mark the end of a meeting session

After completion:

  • Use the resume endpoint to reuse the meeting for a new session
  • Transcriptions and translations remain accessible for viewing

Resume completed meeting

Resume a completed meeting

Resumes a completed meeting by resetting it to ready status and clearing all transcription and translation data. This allows the meeting to be used again for a new session.

What happens when resuming:

  • Meeting status is reset to 'ready'
  • All transcriptions are permanently deleted
  • All translations are permanently deleted
  • Metadata counters (transcriptionCount, translationCount) are reset to 0
  • Snapshot timestamp is cleared
  • Meeting configuration (title, languages, context) is preserved

Requirements:

  • Meeting must be in 'completed' status
  • Only the meeting owner can resume
  • Cannot resume meetings in other states (ready, in_progress, paused)

Generate meeting summary

Generate meeting summary

Generates an AI-powered summary of the meeting transcriptions. The summary is streamed in real-time as it's generated and saved to the meeting record once complete.

Summary generation process:

  • Fetches all transcriptions from the meeting
  • Uses the meeting's target language for the summary
  • Streams the summary content as it's generated
  • Saves the complete summary to the meeting once generation is complete

Requirements:

  • Meeting must be in 'completed' status
  • Meeting must have transcriptions available
  • Summary must not have been generated previously
  • Only the meeting owner can generate summaries

Concurrency control:

  • Uses cache locks to prevent concurrent summary generation
  • Lock expires after 30 seconds
  • Returns error if summary generation is already in progress

Error scenarios:

  • Meeting not completed: Returns 400 with 'meeting_not_completed_for_summary'
  • Summary already generated: Returns 400 with 'summary_already_generated'
  • No transcriptions found: Returns 400 with 'summary_generation_failed'
  • Generation in progress: Returns 400 with 'summary_generation_in_progress'

Create subscription order

Create a new subscription order

Creates a new order for a subscription plan. This endpoint is used exclusively for subscription plan purchases. For purchasing additional credits, use the POST /orders/credit endpoint instead.

Requirements:

  • plan_id is required and must be a valid active plan (sqid)
  • Plan must not be a trial plan
  • redirect_path (optional) must be a relative path without URL scheme

Process flow:

  1. Validates plan_id using SQID encoding
  2. Verifies plan is active and not a trial plan
  3. Creates order record with plan association
  4. Initializes payment via payment gateway (Stripe)
  5. Returns order with payment URL in metadata

Payment completion:

  • User completes payment on gateway's checkout page
  • Gateway sends webhook to /payments/stripe/callback
  • System processes payment and activates subscription plan
  • Plan's included minutes are added to user account

Redirect behavior:

  • If redirect_path is provided, converts it to full URL (e.g., "/dashboard" -> "https://app.example.com/dashboard")
  • After successful payment, user is redirected to the specified URL instead of default success page
  • redirect_path must be a relative path (e.g., "/dashboard/billing")
  • Full URLs with schemes (http://, https://) are rejected by validation

Requirements:

  • User must have an active subscription plan
  • Plan must not be a trial plan (is_trial = false)
  • Quantity must be between 1 and 100 (credit hours)
  • redirect_path (optional) must be a relative path without URL scheme

Process flow:

  1. Validates user has a valid non-trial plan
  2. Creates order with orderable_type = null (credit-only order)

  • System processes payment and adds credit duration to user account

Credit calculation:

  • Each quantity unit = 1 hour (60 minutes) of credit
  • Price per hour is determined by user's current plan configuration
  • Total amount = quantity * hourly_price

Redirect behavior:

  • If redirect_path is provided, converts it to full URL (e.g., "/dashboard/credits" -> "https://app.example.com/dashboard/credits")
  • After successful payment, user is redirected to the specified URL instead of default success page

Get subscription portal URL

Get subscription portal URL

Retrieves a URL to the payment gateway's subscription management portal for managing a completed subscription order. Users can use this portal to:

  • Update payment methods
  • View billing history
  • Cancel or modify subscriptions

Validations:

  • Order must be for a subscription plan (not one-time credits)

Broadcasting

Authenticate for WebSocket broadcasting

Authenticate for WebSocket broadcasting

Authenticates the current user for a specific broadcasting channel/room. Returns a JWT token and full room name for WebSocket connection.

The token includes:

  • User ID (sub claim)
  • Room name
  • Expiration time (TTL from JWT config)

Channel types:

  • Private channels: Requires authentication, prefixed with 'private-'
  • Presence channels: Requires authentication, prefixed with 'presence-'
  • Public channels: No authentication required

Rozeta private channel names:

  • meeting.{meeting_id}
  • meeting.transcription.{meeting_id}
  • meeting.translation.{meeting_id}
  • conversation.{conversation_id} for conversation.started and conversation.paused
  • conversation.transcription.{conversation_id} for transcription.created
  • conversation.translation.{conversation_id} for translation.created
  • command.{user_id} for cross-device command events, where user_id is the authenticated user's sqid

Conversation channel ids are conversation ids returned by POST /api/v1/conversations, not user ids.

If room name doesn't include a prefix, it will be automatically prefixed based on the 'prefix' parameter (defaults to 'private-').

Request Body schema: application/json
required

required
string

Room name to authenticate for (can include or exclude prefix)

Optional channel prefix (defaults to 'private-')

Validates that the authenticated user owns the target meeting or conversation, then broadcasts a command event to the user's private Socket.IO command channel.

Subscribe to command.{user_id}, where user_id is the authenticated user's sqid. Event names:

  • command.goto_meeting
  • command.start_meeting
  • command.pause_meeting
  • command.goto_conversation
  • command.start_conversation
  • command.pause_conversation

Meeting command payloads include { "meeting_id": "<meeting_sqid>" }. Conversation command payloads include { "conversation_id": "<conversation_uuid>" }.
